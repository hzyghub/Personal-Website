# 余额宝资金流入流出预测

## 一句话定位

基于双周期因子分解模型和多源数据融合，预测余额宝未来30天每日申购/赎回总额的天池竞赛项目，最终得分114.82分（自建模型）/ 120.31分（融合易卦特征后），核心创新为双周期因子乘性分解模型和月内10日效应发现。

## 竞赛背景

**赛事全称**：蚂蚁金服天池竞赛——余额宝资金流入流出预测（阿里云天池平台 competition/entrance/231573）

**业务背景**：蚂蚁金服（现蚂蚁集团）拥有上亿余额宝用户，每天涉及大量资金流入和流出。精准预测未来资金流动对于流动性风险管理至关重要——预测偏低会导致资金闲置，预测偏高则可能面临流动性危机。

**数据规模**：
- 用户余额表（user_balance_table）：约2.8万用户、2013年7月至2014年8月共14个月的每日资金流水，150MB+
- 用户画像表（user_profile_table）：用户性别、城市、星座等信息
- 余额宝收益率表（mfd_day_share_interest）：万份收益和七日年化收益率
- SHIBOR银行间同业拆放利率表（mfd_bank_shibor）：隔夜至1年共8个期限的利率

**预测目标**：基于2014年8月31日及之前的数据，预测2014年9月1日至30日共30天的每日申购总额和赎回总额（精确到分，单位：0.01元）。

**评价标准**：
- 每日相对误差 = |真实值 - 预测值| / 真实值
- 相对误差为0时该日得10分，超过0.3则得0分，中间按单调递减函数映射
- 最终总分 = 申购预测得分 x 45% + 赎回预测得分 x 55%
- 理论满分 = 30天 x 10分 x 2项 = 600分，折算后约300分满分

## 数据与问题分析

### 数据特征

训练数据为2014年3月至8月共184天、约2.8万用户的每日资金流水汇总。核心字段包括：
- 申购金额（total_purchase_amt）：包含直接购买和收益自动再投资
- 赎回金额（total_redeem_amt）：包含消费和转出
- 消费类目1-4（category1-4）：不同消费场景的支出
- 转出去向：转出到支付宝余额（tftobal_amt）vs 转出到银行卡（tftocard_amt）

### 核心业务规则

1. **收益确认延迟**：周一至周四申购2天后显示收益，周五申购延迟4天，周六4天，周日3天
2. **周末效应**：周末申购和赎回金额显著低于工作日（约为工作日的63-64%）
3. **申购构成**：今日申购总量 = 支付宝余额购买 + 银行卡购买 + 收益自动购买
4. **复利计算**：余额宝为货币基金，采用"利滚利"复利方式

### 时间序列特点

通过对184天历史数据的分析，发现以下关键模式：

| 模式 | 具体表现 |
|------|----------|
| 周末效应 | 工作日均值309M vs 周末均值196M（降幅36.6%） |
| 周内不对称 | 周二申购峰值（334M），周五低谷（249M） |
| 月内周期 | 月初活跃，月末下降，10日出现异常峰值 |
| 收益驱动 | 申购与2天前收益相关性0.75 |
| 对称性 | 申购和赎回的周末效应几乎完全对称（0.634 vs 0.640） |

## 我的解决方案

### 整体技术路线

项目经历了从基础模型到双周期因子创新模型的演进过程：

```
阶段1: 基础集成模型 (Prophet + ARIMA + 周期因子) → 114.25分
阶段2: 增强版比赛模型 (51维特征 + 多模型集成) → 114.82分
阶段3: 双周期因子创新模型 (weekday x day 分解) → 持续优化
阶段4: 融合易卦特征的三层架构 → 120.31分
```

### 特征工程

从原始数据中构建了155个原始特征（筛选后181个数值特征），分为六大类：

#### 1. 日历特征（42个，占23%）

基础时间特征：
- 年、月、日、星期几、年内周数
- 是否周末、是否工作日、是否周一、是否周五
- 是否月初（前3天）、是否月末（后3天）
- 月内天数进度、距月末天数
- 季度、是否季度末

三角函数周期编码（创新点）：
```python
df['weekday_sin'] = np.sin(2 * pi * weekday / 7)
df['weekday_cos'] = np.cos(2 * pi * weekday / 7)
```
解决了周期性特征"周日和周一相邻"的编码问题。

收益确认延迟特征：
- 根据业务规则计算每日收益确认延迟天数（2-4天不等）
- 标记收益确认日，量化收益驱动效应对申购行为的影响
- 申购与2天前收益相关性高达0.75

#### 2. 滞后特征（45个，占25%）

对申购金额、赎回金额、活跃用户数、总余额四个指标分别构建1-7天滞后特征：
- purchase_lag_1 至 purchase_lag_7
- redeem_lag_1 至 redeem_lag_7
- active_users_lag_1 至 active_users_lag_7
- total_balance_lag_1 至 total_balance_lag_7

#### 3. 滚动窗口统计特征（48个）

对四个核心指标在3天、7天、14天、30天四个窗口上分别计算：
- 移动平均（ma）：捕捉趋势
- 标准差（std）：衡量波动性
- 最小值（min）和最大值（max）：刻画区间

余额趋势特征：
```python
df['balance_trend_7'] = (total_balance - balance_ma_7) / balance_ma_7
```

- 期限利差：shibor_spread_1w_1m（1周与1月利差）、shibor_spread_on_1w（隔夜与1周利差）

### 双周期因子模型（核心创新）

#### 什么是双周期因子

余额宝资金流数据中存在两个独立的周期性维度：
- **weekday因子**：周内不同星期的规律（周一到周日共7个因子）
- **day因子**：月内不同日期的规律（1号到31号共31个因子）

传统方法通常只考虑其中一个维度（如只做周内模式），双周期因子模型将两个维度同时建模并进行乘性分解。

#### 具体方法

**第一步：计算基础水平**
```
base_level = 历史数据日均值
```
申购基础水平约260M，赎回基础水平约257M。

**第二步：独立计算两类因子**

weekday因子（周内相对系数）：

| 星期 | 申购因子 | 赎回因子 |
|------|---------|---------|
| 周一 | 1.060 | 1.128 |
| 周二 | 1.081 | 1.049 |
| 周三 | 1.039 | 1.036 |
| 周四 | 1.017 | 0.918 |
| 周五 | 0.806 | 0.873 |
| 周六 | 0.633 | 0.599 |
| 周日 | 0.635 | 0.681 |

day因子（月内日期相对系数）：
- 对1-31号分别计算历史均值相对于总体均值的比值
- 至少需要3个样本才纳入计算，确保统计稳定性

**第三步：乘性分解预测**
```python
prediction = base_level * weekday_factor * day_factor
```
对每一天的预测，同时乘以对应的weekday因子和day因子。

**第四步：后处理调节**
- 周末效应调节：对周末日期乘以额外的周末衰减系数
- 月初/月末效应：月初提升、月末降低
- 净流入目标控制：根据历史规律调节申购赎回比例
- 变异性控制：通过平滑因子控制变异系数在合理区间

#### 为什么说创新

1. **双维度解耦**：将周内模式和月内模式独立提取再组合，而非将时间作为一个单一维度处理
2. **乘性而非加性**：两个因子的乘法关系更符合金融数据的非线性特征
3. **可解释性强**：每个因子都有明确的业务含义，可以直接与用户行为规律对应
4. **参数可调**：周末系数、平滑度、净流入目标等参数可以独立调节

### 10号效应（关键发现）

#### 发现了什么

在对月内日期因子（day因子）的分析中，发现每月10日的申购金额存在显著的峰值效应。具体数据：

- 10日申购因子约为1.248，即10日的申购金额比月均水平高出约25%
- 这一效应在工作日尤为明显（10日恰好落在工作日时效应更强）
- 赎回也有类似但较弱的效应（10日赎回因子约1.124）

#### 怎么发现的

在构建day因子时，对1-31号分别计算历史申购/赎回均值相对于总体均值的比值。通过因子排序发现10日的因子值显著高于相邻日期，且这一模式在多个月份中重复出现。

月内阶段分析验证：
```
月初(1-10日): 因子均值较高
月中(11-20日): 因子均值回落
月末(21-31日): 因子均值最低
```

10日恰好是月初高活跃期的末尾，可能是发薪日效应导致的资金集中流入。

#### 业务含义

1. **发薪日效应**：许多企业在每月10日前后发放工资，大量用户将工资转入余额宝
2. **规律性资金流入**：这一效应可被用于精确定位资金流入的高峰日期
3. **预测优化**：在模型中对10日施加额外的提升系数（workday_10th_boost），有效改善该日的预测精度

### 模型策略

项目采用了多层次的模型策略，不同模型承担不同角色：

#### Prophet（趋势与季节性分解）

角色：捕捉数据中的长期趋势和季节性周期。

配置要点：
- growth='linear'：余额宝整体为线性增长趋势
- seasonality_mode='multiplicative'：乘法季节性，金额随时间增长时季节性效应同步放大
- changepoint_prior_scale=0.01-0.08：控制趋势变化敏感度
- 自定义周末效应季节性（period=7, fourier_order=3）
- 外部回归变量：SHIBOR利率、万份收益、活跃用户数

#### XGBoost + LightGBM（梯度提升集成）

角色：处理非线性特征交互，学习复杂的特征组合模式。

- XGBoost在申购预测上表现显著更优（MAE: 430万 vs LightGBM的1260万）
- LightGBM在赎回预测上略优（MAE: 1245万 vs XGBoost的1288万）
- 集成权重根据验证集MAE动态计算：`weight = 1 / (mae + epsilon)`
- 最终集成权重：申购 XGB=74.5%/LGB=25.5%，赎回 XGB=49.2%/LGB=50.8%

#### ARIMA（统计稳定性）

角色：提供统计基准，补充机器学习模型可能忽略的线性模式。

- 使用ARIMA(5,1,4)参数
- 对数变换后差分，保证平稳性
- 预测后反对数变换还原

#### 模型融合策略

```
最终预测 = 动态加权融合(Prophet, ARIMA) + 周期因子调整 + 平滑后处理
```

融合权重基于模型预测值与历史最近数据点的跳跃程度动态计算——跳跃越小（越平稳），权重越大。

最终得分最高的增强版比赛模型使用了随机森林 + 梯度提升 + 线性回归的三模型集成，配合51维综合特征工程。

## 关键技术决策与思考

### 1. 训练数据范围选择

使用2014年3月至8月的数据（184天）而非全部14个月的数据。理由：2013年数据中用户行为模式与2014年存在显著差异，使用更近期的数据能获得更稳定的模型。赛题QA也确认"13年的数据选手可以不用，但如果用上效果可能更好"。

### 2. 周末效应的精准建模

通过数据分析发现真实的周末效应系数在0.50-0.65之间。114分双雄模型的对比验证了这一点：
- 冠军模型使用保守系数0.52 → 114.82分
- 亚军模型使用历史匹配系数0.64 → 114.25分
- 过高（>0.70）或过低（<0.45）的周末系数都导致得分下降

### 3. 变异性控制

真实数据具有一定波动性（CV约0.31），但114分成功模型的经验表明需要适度降低变异系数至0.19-0.26区间。过度平滑（CV<0.15）会丢失真实波动信息，过度波动则增加预测误差。

### 4. 收益确认延迟的系统性建模

余额宝的收益确认延迟（T+2至T+4）是影响申购行为的关键因素。通过将这一业务规则显式编码为特征（yield_confirmation_delay），并计算申购与不同天数前收益的交叉相关性，有效捕捉了收益驱动申购的行为模式。

### 5. SHIBOR缺失值处理

SHIBOR利率在节假日没有数据，采用前向填充（forward fill）处理，保证特征连续性。

## 项目亮点（适合展示在简历/作品集的）

1. **双周期因子分解模型**：原创性地将资金流时间序列的周内模式（weekday因子）和月内模式（day因子）进行乘性分解，比传统单一维度时间特征更好地捕捉周期性规律。这一方法可推广到其他具有多周期叠加特征的时间序列预测场景。

2. **10号效应发现**：从数据中发现每月10日存在显著的申购峰值效应（因子值1.248），可能与发薪日资金流入规律相关。这一发现不仅提升了预测精度，也揭示了用户资金行为的月内模式。

3. **深度业务理解驱动的特征工程**：将余额宝收益确认延迟规则（T+2至T+4天不等）显式编码为特征，发现申购与2天前收益的相关性高达0.75，体现了"业务理解 > 算法复杂度"的建模理念。

4. **多模型动态融合**：构建了Prophet（趋势/季节性分解）、XGBoost/LightGBM（非线性交互）、ARIMA（统计基准）三个模型的动态加权融合框架，权重根据各模型在验证集上的表现实时调整。

5. **从114分到120分的系统化优化**：通过114分双雄模型的深度对比分析（冠军vs亚军的周末效应、变异系数、净流入策略差异），提炼出得分关键因素，最终通过融合创新特征实现了分数突破。
