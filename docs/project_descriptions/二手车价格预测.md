# 二手车价格预测

## 一句话定位

阿里天池学习赛——基于深度特征工程（31 -> 163 -> 60）与多模型智能融合（XGBoost x3 + LightGBM x2），将二手车价格预测MAE从基线650降至486，提升25.2%。

## 竞赛背景

这是阿里天池平台的「二手车价格预测」学习赛，面向竞赛新人设计的数据挖掘入门赛题。赛题来源于某交易平台的真实二手车交易记录，要求选手通过机器学习预测二手车的交易价格，属于典型的回归问题。

- **数据规模**：总数据量超过40万条，从中抽取15万条作为训练集，5万条作为测试集A，5万条作为测试集B
- **评价标准**：MAE（Mean Absolute Error），越低越好
- **特征维度**：31列变量，其中15列为匿名变量（v_0 ~ v_14）
- **脱敏字段**：name、model、brand、regionCode 均已脱敏处理
- **竞赛性质**：学习赛（非商业赛），鼓励 Notebook 分享

## 数据与问题分析

### 数据字段

数据包含以下几类特征：

| 类别 | 字段 | 说明 |
|------|------|------|
| 基础信息 | SaleID, name | 交易ID和汽车交易名称（已脱敏） |
| 时间特征 | regDate, creatDate | 注册日期和上线售卖日期 |
| 车辆特征 | brand, model, bodyType, fuelType, gearbox | 品牌、车型、车身类型、燃油类型、变速箱 |
| 核心数值 | power, kilometer | 发动机功率（0-600）、已行驶公里数（万km） |
| 交易信息 | seller, offerType, regionCode, notRepairedDamage | 销售方、报价类型、地区、是否未修复损坏 |
| 匿名特征 | v_0 ~ v_14 | 15个匿名数值特征（重要预测因子） |
| 预测目标 | price | 二手车交易价格 |

### 核心难点

1. **匿名特征占比高**：15个 v 系列特征含义不明，需要通过统计方法挖掘其价值
2. **数据存在异常值**：部分功率值超范围，存在缺失值和非数值标记（如 '-'）
3. **过拟合风险大**：初期模型验证集MAE ~600，但提交到测试集成绩飙升到6000+，说明严重过拟合
4. **特征构造空间大**：31个原始特征之间存在复杂的非线性关系，如何有效组合是关键

## 我的解决方案

整体方案经历了从基线探索到最终突破的五个阶段，每一步都有明确的技术贡献。

### 特征工程（核心亮点）

特征工程是本项目最大的技术投入，将31个原始特征扩展到163个候选特征，再通过特征选择精炼到60个。

#### 第一层：核心数值特征的多重数学变换

对 power（功率）和 kilometer（公里数）这两个最重要的数值特征，进行多种数学变换以捕获非线性关系：

- **对数变换**：`log1p(x)` —— 压缩长尾分布
- **平方根变换**：`sqrt(x)` —— 缓解偏度
- **多项式变换**：`x^2, x^3` —— 捕获高阶非线性
- **倒数变换**：`1/(x+1)` —— 反转量纲关系
- **排名变换**：`rank(pct=True)` —— 转化为均匀分布的分位排名
- **Z-score 标准化**：`(x - mean) / std`
- **分箱特征**：用 `qcut` 进行等频分箱（5/10/20/50分位）

#### 第二层：车龄与时间特征深度挖掘

从 `regDate`（注册日期，格式如20160101）提取时间维度：

- 车龄计算：`car_age = 2020 - regDate_year`（以2020年为基准）
- 车龄的多重变换：`log, sqrt, square, cube, inverse`
- 注册月份和季节的周期性编码：`sin(2*pi*month/12), cos(2*pi*month/12)`
- 年平均行驶里程：`kilometer / (car_age + 1)`

#### 第三层：v 系列匿名特征的深度挖掘

15个匿名特征是最具挑战性的信息源，处理策略包括：

- 每个 v 特征的独立变换：`log, sqrt, square, inverse, rank, zscore`
- v 系列聚合统计：`sum, mean, std, max, min, range, median, skew, kurtosis`
- v 系列内部交互：`v_0/v_1, v_0-v_3, v_2*v_4, v_0*v_1/(v_3+1)` 等比率、差值、乘积
- v 与 power/kilometer 的交叉特征：比率、乘积、差值

#### 第四层：交互特征构造

组合不同维度的信息：

- 功率-车龄交互：`power * car_age, power / (car_age + 1), power * log(car_age)`
- 里程-车龄交互：`kilometer * car_age, kilometer / (car_age + 1)`
- 功率-里程交互：`power/(km+1), power*km, power-km, power+km`，以及调和平均和几何平均
- 综合效率特征：`kilometer / (car_age * power + 1)`

#### 第五层：基于贝叶斯平滑的目标编码

对类别特征进行目标编码时，使用贝叶斯平滑防止过拟合：

```
smoothed_mean = (category_mean * category_count + global_mean * alpha) / (category_count + alpha)
```

- 对 brand、model、regionCode 进行平滑目标编码（alpha=50~200）
- 同时编码均值和标准差信息
- 对 brand + bodyType 的组合进行交叉目标编码

#### 第六层：品牌级别统计特征

按品牌分组，计算车辆属性在品牌内的相对位置：

- 品牌内 power/kilometer 的 `mean, std, min, max, skew`
- 个体值与品牌均值的偏差：`value - brand_mean`
- 个体值与品牌均值的比率：`value / (brand_mean + 1)`
- 品牌内 Z-score：`(value - brand_mean) / (brand_std + 1)`

### 特征选择

从163个候选特征中精选60个，采用4种方法的融合评分机制：

#### 4种特征选择方法

| 方法 | 权重 | 原理 |
|------|------|------|
| f_regression（F检验） | 0.25 | 统计方法，衡量特征与目标的线性相关性 |
| mutual_info_regression（互信息） | 0.25 | 信息论方法，捕获非线性依赖关系 |
| RandomForest importance（随机森林重要性） | 0.30 | 树模型方法，基于分裂增益评估特征价值 |
| Lasso coefficient（Lasso系数） | 0.20 | 正则化方法，通过L1惩罚自动筛选特征 |

#### 融合评分机制

每个特征在4种方法中分别获得归一化分数，加权求和得到综合评分：

```
score(feature) = 0.25 * f_score_norm + 0.25 * mi_score_norm + 0.30 * rf_importance_norm + 0.20 * lasso_coef_norm
```

此外，在评分之前先执行预处理：
1. 移除常数特征（唯一值 <= 1 的列）
2. 移除高相关特征（相关系数 > 0.98 的冗余列）

最终按综合评分降序排列，取前60个特征进入模型训练。

### 模型策略

最终使用5个梯度提升模型变体的集成，分为 XGBoost 和 LightGBM 两大阵营：

#### 5个模型的配置差异

| 模型 | n_estimators | max_depth | learning_rate | subsample | colsample | reg_alpha | reg_lambda | 权重 |
|------|-------------|-----------|---------------|-----------|-----------|-----------|------------|------|
| xgb_ultra_aggressive | 2500 | 7 | 0.08 | 0.9 | 0.9 | 0.5 | 0.5 | 28.34% |
| xgb_deep | 2000 | 8 | 0.05 | 0.8 | 0.8 | 2.0 | 2.0 | 25.85% |
| lgb_ultra_optimized | 3000 | 6 | 0.06 | 0.85 | 0.85 | 1.0 | 1.0 | 21.58% |
| xgb_optimized | 3000 | 6 | 0.06 | 0.85 | 0.85 | 1.0 | 1.0 | 16.99% |
| lgb_deep | 2500 | 7 | 0.05 | 0.8 | 0.8 | 2.0 | 2.0 | 7.24% |

#### 为什么选择这种组合

- **XGBoost 占3席**：XGBoost 在各阶段实验中稳定表现最好，通过不同深度和正则化强度引入多样性
  - ultra_aggressive（深度7、弱正则）：捕获复杂交互模式
  - deep（深度8、强正则）：深层特征学习但防止过拟合
  - optimized（深度6、中等正则）：稳健的中间配置
- **LightGBM 占2席**：与 XGBoost 的叶子生长策略不同（LightGBM 是叶子优先），引入算法层面的多样性
  - ultra_optimized：标准配置，中等正则化
  - deep：更深模型配合更强正则化
- **关键设计**：5个模型的树深度、学习率、正则化强度各不相同，确保模型之间的预测差异性，这是集成有效的核心前提

### 模型融合

#### 权重优化方法

使用 scipy.optimize.minimize 的 SLSQP 方法求解最优融合权重：

```python
from scipy.optimize import minimize

def objective(weights):
    weights = weights / weights.sum()  # 归一化
    ensemble_pred = np.dot(pred_matrix, weights)
    mae = mean_absolute_error(y_true, ensemble_pred)
    regularization = 0.01 * np.sum(weights ** 2)  # 鼓励使用更多模型
    return mae + regularization

constraints = {'type': 'eq', 'fun': lambda w: w.sum() - 1}
bounds = [(0, 1) for _ in range(n_models)]
```

#### 优化策略

- **多次随机初始化**：从10个不同的 Dirichlet 随机初始点出发，取最优解，避免陷入局部最优
- **正则化约束**：在目标函数中加入 `0.01 * sum(w^2)` 鼓励权重分散到更多模型
- **约束条件**：权重和等于1、每个权重在 [0, 1] 区间
- **预测矩阵**：使用5折交叉验证的 Out-of-Fold（OOF）预测值构建

#### 验证策略

- 采用5折分层交叉验证（StratifiedKFold）
- 按 price 分10箱进行分层，确保各折的目标分布一致
- 每个模型在各折上训练并产生 OOF 预测，用于权重优化

## 关键技术决策与思考

### 从严重过拟合到有效泛化

项目初期最大的挫折是：验证集 MAE 约600，但提交到天池后分数飙升到6000+。排查后发现原因：使用了 testA 的数据进行训练，导致数据泄漏。切换到 testB 后，集成模型提交成绩直接降到600左右。

### 特征工程 vs 模型复杂度的取舍

实验中发现：
- 过于激进的特征工程（几百个特征不加筛选）反而降低泛化能力
- 保守的特征工程（只保留最确定的30-40个特征）限制了上限
- 最终在163个候选特征中精选60个，达到最优平衡

### 模型多样性的价值

单纯使用 XGBoost 的不同参数配置，集成收益有限。引入 LightGBM 后，由于两种算法的树生长策略本质不同（XGBoost 按层生长 vs LightGBM 按叶子生长），集成效果显著提升。

### 验证策略的演进

- **早期**：Holdout 验证（70/30 或 80/20 划分）—— 验证不稳定
- **中期**：5折交叉验证 —— 更稳定的评估，但权重优化仍在同一折上
- **最终**：5折分层交叉验证 + OOF 预测权重优化 —— 最稳健的方案
